# ADR 0005 — 网页捕获以 URL 为业务身份，重抓覆盖

**状态**：已接受（2026-09-19，grill-with-docs 轮裁定）

## 背景

网页内容会变。同一篇文章过段时间重抓，正文不同 → sha256 不同。若沿用文件捕获的"内容哈希即身份"规则，知识库会堆同一文章的多个版本；若引入版本机制，则超出个人工作台的范围。

## 决策

**同 URL 重抓 = 覆盖原文档**：删旧建新、标签保留迁移、不留历史版本。URL 是网页文档的业务身份；sha256 仍是去重手段（重抓内容完全相同则幂等跳过）。URL 触发边界：捕获输入 trim 后整体为一个合法 http/https URL 才走抓取，混有其他文字一律纯文本捕获。

## 后果

- 知识库存"现在的认知"，永远只有一个最新版；版本历史归将来的 Git 同步（M3 候选）管。
- 覆盖实现 = 复用删除文档的索引清理 + 重新登记，标签先行读出后回填。
- 抓取时间戳在元信息头中留痕，"旧版内容丢失"是接受的行为而非缺陷。
