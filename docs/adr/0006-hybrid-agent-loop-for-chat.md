# ADR 0006 — 对话深挖采用混合式：固定首检索 + agent 工具循环

**状态**：已接受（2026-09-19，grilling 第三轮 + 实现验证）

## 背景

M0 的固定管线（每条消息自动检索 top6 注入）快、便宜、行为可预期，但回答不了"把第 3 篇文档展开讲讲"这类深挖请求。纯 agentic（模型自己决定查不查）灵活，但每条消息绕 agent loop（慢、贵），且存在"不查就瞎答"的回归风险——而"开口就带出处"是产品底线。

## 决策

**两段式混合**：每条消息仍先固定检索 top6 注入（出处底线），在此之上挂 `pi-agent-core` 的 `runAgentLoop`，模型可按需调用三个工具——`kb_search`（换词补检索）、`kb_read`（读指定文档全文/指定页）、`kb_list`（文档清单）。工具总预算 8 次（超限工具结果返回 terminate 提示模型直接作答）。图片问答走 vision 档单轮，**不挂工具**（降低不稳定面），且图片仅当轮可见不入库。

## 后果

- 延迟与成本：深挖请求多轮 LLM 调用是接受的成本；普通请求仍是一条管线。
- SSE 协议新增 `tool` 事件，前端显示"🔧 工具调用中"。
- 工具面刻意克制（三个），新工具加入需过"高频且固定管线做不到"门槛。
- 实测验证：deepseek-v4-pro 能正确调用 kb_read 并如实回答（含"这篇笔记只有一句话"的诚实场景）。
